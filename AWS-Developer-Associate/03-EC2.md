# Amazon EC2 (Elastic Compute Cloud)

## 1. EC2 Fundamentals

**Amazon Elastic Compute Cloud (EC2)** provides scalable compute capacity on AWS. An EC2 instance is typically a virtual server, though some instance types offer bare-metal access.

**IaaS (Infrastructure as a Service)** is a cloud model in which a provider supplies computing resources such as virtual servers. AWS provides these servers through EC2 and manages the physical infrastructure. Customers manage the guest operating system and applications.

When launching an instance, you choose an **instance type** for its compute and networking capacity, an **Amazon Machine Image (AMI)** for its operating system and initial software, and storage for its data. The instance type determines available resources such as vCPUs, memory, network bandwidth, and support for local disks.

| Related service or resource | Role |
| --- | --- |
| Elastic Load Balancing (ELB) | Distributes incoming traffic across registered targets, such as EC2 instances. |
| Auto Scaling group (ASG) | Uses Amazon EC2 Auto Scaling to maintain desired instance capacity and adjust it based on configured policies or schedules. |

In a typical web architecture, users send requests to a load balancer, which routes traffic to EC2 instances in an Auto Scaling group. Each instance runs the application. See [EC2 Storage](04-EC2-Storage.md) for storage options.

## 2. EC2 Instance Types

### Reading an Instance Type Name

In `m5.2xlarge`, **m** is the general purpose series, **5** is the generation, and `2xlarge` is the size. The series and generation together identify the `m5` family. A family name can also include options, such as the **i** in `c7i.large`, which indicates an Intel processor. Newer generations can improve performance or efficiency. [EC2 instance type naming conventions](https://docs.aws.amazon.com/ec2/latest/instancetypes/instance-type-names.html)

### Instance Families by Workload

EC2 groups instance families into categories based on the workloads they serve. Choose a family based on the application's primary resource needs, such as CPU, RAM, storage, or hardware acceleration. Then compare cost, availability, processor architecture compatibility, and expected utilization.

| Category | Example series | What it prioritizes | Example workloads |
| --- | --- | --- | --- |
| General purpose | M, T | Balanced CPU, memory, and networking | Web and application servers, REST APIs, React and Node.js applications, development and testing environments, code repositories, and small to midsize applications |
| Compute optimized | C | CPU performance | Batch processing, media transcoding, image resizing and compression, high-performance web and application servers, dedicated gaming servers, scientific modeling, and CPU-intensive machine learning |
| Memory optimized | R, X | RAM capacity and performance | Relational and NoSQL databases, Redis and other distributed caches, in-memory databases, business intelligence, real-time processing of large unstructured datasets, and large-scale data analysis |
| Storage optimized | I, D, H | High throughput, high IOPS, or low latency on local storage | High-frequency online transaction processing (OLTP), databases with heavy local I/O, data warehouses, distributed file systems, local data caches, and storage-intensive big data workloads such as self-managed Elasticsearch |
| Accelerated computing | P, G, F | GPUs for compute (P) or graphics (G), and field-programmable gate arrays (FPGAs) for programmable acceleration (F) | AI model training and inference, graphics and video rendering, and scientific computations that can use accelerators |
| High-performance computing (HPC) | Hpc | Compute performance, memory bandwidth, and fast communication between instances | Scientific simulations, computational fluid dynamics, weather modeling, and large-scale engineering calculations |

For CPU-bound image processing such as resizing, compression, or format conversion, compare C-series types such as `c5.large`, `c6i.large`, and `c7i.large`. For memory-intensive workloads, compare the R series with higher-memory X-series configurations. For example, a Redis cache can use extra RAM to hold a larger working set for low-latency access. [EC2 instance type categories and families](https://docs.aws.amazon.com/ec2/latest/instancetypes/instance-types.html) · [Accelerated computing instance specifications](https://docs.aws.amazon.com/ec2/latest/instancetypes/ac.html)

### Instance Sizing and Hardware

- **Instance size** determines how much CPU, memory, and other capacity an instance has. Larger sizes within a family typically offer more resources at a higher cost.
- **Burstable instances (T series)** provide baseline CPU performance and use CPU credits to temporarily burst above that baseline. They suit workloads with variable CPU demand. `t2.micro` is a common introductory example. M-series instances offer balanced resources for steadier demand.
- **Bare metal instances** let the operating system run directly on the physical server and access its processors and memory. AWS uses `metal` in the instance size name for these options. [EC2 instance type naming conventions](https://docs.aws.amazon.com/ec2/latest/instancetypes/instance-type-names.html)

## 3. Launching and Configuring Instances

### Amazon Machine Images

An **Amazon Machine Image (AMI)** is a reusable template used to launch EC2 instances. It provides the operating system and can include applications, dependencies, system settings, and monitoring tools. Launch permissions control who can use the image.

- **AWS-provided AMIs** are maintained by AWS. Other AMIs can be public or shared with specific accounts.
- **AWS Marketplace AMIs** can include third-party software charges.
- **Custom AMIs** come from an instance you configure. For example, install Node.js, application dependencies, and monitoring tools before creating an AMI. New instances launched from that image start with the same software baseline, which speeds up deployment and avoids repeating setup.

AMIs are Region-specific and can be copied to another Region. Choose an AMI in the launch Region with a processor architecture compatible with your instance type. [Amazon Machine Images](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AMIs.html)

See [EBS-Backed AMIs](04-EC2-Storage.md#ebs-backed-amis) for how EC2 creates and attaches volumes at launch.

### EC2 User Data and Bootstrapping

**Bootstrapping** is the automatic configuration of a machine during startup. You can supply **EC2 user data** at launch so the instance's initialization agent can install updates or dependencies, download files, configure an application, and start services. For example, an Amazon Linux 2023 instance can use user data to install Apache, start it, enable it for future boots, and publish a basic page.

On standard Linux AMIs that use cloud-init, user data shell scripts run as root and run only on the first boot by default. You can configure startup tasks to run on subsequent boots. Exact behavior depends on the AMI, operating system, and initialization agent. Keep credentials and other secrets out of user data. [EC2 user data](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/user-data.html)

## 4. Instance Lifecycle

| State | Meaning |
| --- | --- |
| **pending** | The instance is preparing to enter the running state. |
| **running** | The instance is running. Application startup may still be in progress. |
| **stopping** | The instance is transitioning to the stopped state. |
| **stopped** | The instance is powered off and can be started again. |
| **shutting-down** | The instance is being terminated. |
| **terminated** | The instance has been permanently removed and cannot be restarted. |

- **Reboot** restarts the operating system on the same host. Instance compute billing continues.
- **Stop and start** powers off an EBS-backed instance and lets you start it again later. Instance compute charges stop while the instance is stopped. Other allocated resources can still incur charges.
- **Hibernate** saves the contents of RAM so a supported, configured instance can resume with its previous memory state.

See [EC2 Storage](04-EC2-Storage.md) for what happens to data during these actions and at termination. [EC2 instance lifecycle](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-lifecycle.html)

## 5. Network Security and Instance Access

Network access to an EC2 instance depends on the network path and the rules that permit traffic. **SSH (Secure Shell)** lets you securely connect to a Linux instance to run commands remotely.

### Security Groups

A **security group** is a stateful virtual firewall that filters traffic at the network interface. **Inbound** traffic enters the instance, such as a user's HTTPS request. **Outbound** traffic leaves the instance, such as a request for an external dependency. For a tracked connection, response traffic is allowed automatically. For example, an instance that makes an allowed outbound HTTP request can receive the reply without a separate inbound rule.

Rules specify a protocol, such as TCP, UDP, or ICMP, and a port or range when applicable. Inbound rules specify a source, and outbound rules specify a destination. You can use IPv4 or IPv6 ranges, prefix lists, or other security groups where supported. Rule descriptions are optional. Security groups use allow rules, so unmatched traffic is implicitly denied. Traffic dropped by a security group never reaches the guest operating system. [Security group rules](https://docs.aws.amazon.com/vpc/latest/userguide/security-group-rules.html)

- A **newly created security group** starts with no inbound rules and an outbound rule that allows all traffic. You can change those rules.
- A **VPC's default security group** initially allows inbound traffic from resources associated with that same group and allows outbound traffic. [Default VPC security groups](https://docs.aws.amazon.com/vpc/latest/userguide/default-security-group.html)
- Multiple instances can share a security group, and an instance's network interface can have multiple groups. Their allow rules are combined. Rule changes apply to associated resources without an instance restart.
- A security group is created in a VPC. Eligible groups can also be associated with other VPCs in the same Region. [Security Group VPC Associations](https://docs.aws.amazon.com/vpc/latest/userguide/security-group-assoc.html)

### CIDR and Inbound Rule Examples

**CIDR (Classless Inter-Domain Routing)** uses a prefix length to specify an IP address range. `0.0.0.0/0` covers all IPv4 addresses, and `::/0` covers all IPv6 addresses. `192.168.1.0/24` covers addresses from `192.168.1.0` through `192.168.1.255`, and `203.0.113.10/32` represents one IPv4 address.

| Traffic | Protocol | Port | Example source |
| --- | --- | --- | --- |
| HTTP | TCP | 80 | `0.0.0.0/0` for a public website |
| HTTPS | TCP | 443 | `0.0.0.0/0` for a public website |
| SSH | TCP | 22 | The administrator's public IPv4 address with a `/32` prefix |
| Custom application | TCP | 4567 | `0.0.0.0/0` if the application is intended to be public |

Restrict administrative SSH to trusted sources. A separate SSH security group can make those access rules easier to manage.

### EC2 Instance Connect

**EC2 Instance Connect** uses AWS Identity and Access Management (IAM) to authorize SSH key delivery to a supported Linux instance. After AWS checks the caller's IAM permissions, EC2 Instance Connect makes a temporary SSH public key available through instance metadata for **60 seconds**. The instance's SSH service uses it to authenticate the connection. The 60-second window applies to authentication, and the established session can continue beyond it. [How EC2 Instance Connect works](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connect-linux-inst-eic.html)

The instance needs EC2 Instance Connect software, and the caller needs IAM permissions and a working network path to the instance. For a standard public console connection, allow inbound SSH from the regional EC2 Instance Connect service prefix list. An **EC2 Instance Connect Endpoint** can provide a path to private instances without public IP addresses when IAM permissions, routing, and security group rules allow it. [Connection prerequisites](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-connect-prerequisites.html) · [EC2 Instance Connect Endpoint](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connect-using-eice.html)

For the public console workflow, open **EC2 → Instances**, select the instance, and choose **Connect → EC2 Instance Connect**. Choose the connection settings, verify the username, and select **Connect** to open a browser terminal. [Console connection steps](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-connect-methods.html)

The console manages the temporary key for you. EC2 Instance Connect also supports a separate SSH client with your own key. Traditional SSH can use a key already authorized on the instance or another configured authentication method. [EC2 Instance Connect methods](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-instance-connect-methods.html)

### Troubleshooting Connections

| Symptom | What it usually means | Possible causes |
| --- | --- | --- |
| **Connection timed out** | The client received no response before its deadline. | Security group or network ACL restrictions, incorrect routing, an unavailable instance, or a firewall dropping traffic |
| **Connection refused** | The connection was actively rejected. | An application that is stopped or listening on a different port, or an operating-system firewall rejecting the connection |

## 6. IAM Roles for Applications on EC2

An **IAM role** is an AWS identity that authorized entities can assume. Applications running on EC2 can use a role to obtain temporary credentials for AWS services such as Amazon S3, Amazon DynamoDB, Amazon SQS, and Amazon CloudWatch. An **instance profile** associates the role with the EC2 instance. [IAM roles for Amazon EC2](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/iam-roles-for-amazon-ec2.html)

To let a Node.js application list and read objects in an S3 bucket, configure the role as follows.

1. Create an IAM role that trusts the EC2 service.
2. Attach a permissions policy granting `s3:ListBucket` on the bucket and `s3:GetObject` on the required objects.
3. Associate the role with the instance through an instance profile.
4. Let the AWS SDK use its default credential provider chain. It can retrieve and refresh temporary credentials using the **Instance Metadata Service (IMDS)**.

The role's permissions govern which AWS API actions the application can take on which resources. The security group governs the network connection to the relevant endpoint.

Use **least privilege** by granting only the actions and resources the application requires, and review those permissions periodically. Use role credentials in place of hardcoded access keys, and require **IMDSv2** when the software on the instance supports it.

## 7. EC2 Purchasing Options

### Flexible and Interruptible Usage

- **On-Demand Instances** charge for compute usage without a long-term commitment. They suit unpredictable traffic, development and testing, and short-lived workloads such as a temporary API server.
- **Spot Instances** use spare EC2 capacity at a discount. Available capacity can change, and EC2 can interrupt the instance. EC2 issues a best-effort notice two minutes before a Spot stop or termination. If the configured interruption behavior is hibernation, hibernation begins immediately. Spot suits retryable workloads such as batch jobs, background processing, or distributed image processing that can resume interrupted work. [Spot interruption notices](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/spot-instance-termination-notices.html)

### Discounts for Consistent Usage

- **Reserved Instances (RIs)** are one- or three-year billing commitments that discount matching EC2 usage. They come in Standard and Convertible offerings and suit stable production workloads or long-running servers. A **regional RI** supplies a billing discount across the Region. A **zonal RI** also reserves matching capacity in its specified Availability Zone. [Regional and zonal Reserved Instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/reserved-instances-scope.html)
- **Savings Plans** discount eligible compute usage in exchange for a one- or three-year spending commitment measured in dollars per hour. A **Compute Savings Plan** can apply across EC2 instance families and Regions and to eligible AWS Fargate and AWS Lambda usage. An **EC2 Instance Savings Plan** applies to a specific instance family in a specific Region, with flexibility across sizes within that family. [Savings Plans types](https://docs.aws.amazon.com/savingsplans/latest/userguide/plan-types.html)

### Dedicated Hardware

**Single tenancy** means a physical server is reserved for one tenant. For EC2 Dedicated Instances, AWS isolates the hardware to one AWS account. Instances from that account can share the same server, including instances with default tenancy. [Amazon EC2 Dedicated Instances](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/dedicated-instance.html)

| Option | What it provides | Typical reason to choose it |
| --- | --- | --- |
| **Dedicated Hosts** | A physical server dedicated to your use, with visibility into the host and control over instance placement. Term commitments depend on the purchase option. | Server-bound software licensing, compliance, or host-level placement requirements |
| **Dedicated Instances** | EC2 instances on single-tenant hardware with AWS-managed placement. On-Demand pricing is available without a long-term commitment. | Hardware isolation with AWS-managed placement |

[EC2 purchasing and tenancy options](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instance-purchasing-options.html)

### Capacity Assurance

**On-Demand Capacity Reservations** hold matching EC2 capacity in a specific Availability Zone. Immediate-use reservations require no fixed term. Future-dated reservations have a commitment period. Reserved capacity generally incurs charges even when unused. The reservation supplies capacity assurance, and an eligible Savings Plan or regional RI can supply a billing discount. [On-Demand Capacity Reservations](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/ec2-capacity-reservations.html)
